# 🤖 Python 多功能智能助手 v2.8

基于 **Flask + LangChain** 的全栈 AI 对话系统。支持**用户登录注册**、**SSE 流式 Markdown**、**双引擎 TTS**、**角色绑定**、**文件附件**，以及**多用户隔离的知识库问答与分享**（Milvus 向量检索）。

## 2. 快速开始

### 2.1 环境要求

- Python ≥ 3.11
- MySQL 8.0（需运行中）
- （可选）Redis 7.0
- （知识库向量检索）Milvus 2.x，本机 `http://localhost:19530`；未启动时自动回退关键词检索

### 2.2 安装

```bash
cd E:\PythonAssistant
pip install -r requirements.txt
```

### 2.3 配置

编辑 `.env`，至少填入 DeepSeek API Key：

```env
DEEPSEEK_API_KEY=sk-你的密钥
# 可选：通义千问（知识库 embedding 也使用此 Key）
# QWEN_API_KEY=sk-你的密钥
```

数据库首次启动自动创建。

### 2.4 启动

```bash
python run.py
```

浏览器打开 **http://localhost:5000** → 自动跳转登录页 → 注册账号 → 开始聊天。

### 2.5 生产部署

```bash
gunicorn -c gunicorn_config.py run:app
```

详见 [deploy.md](deploy.md)。

## 4. 使用教程

### 4.1 注册登录

打开 http://localhost:5000/login → 点击"没有账号？立即注册" → 输入用户名（≥2位）和密码（≥6位）→ 自动跳转聊天页。

> 手机验证码、微信/QQ扫码登录 UI 已就绪，因需企业营业执照暂不可用。

每个用户登录后只能看到**自己的**对话和角色。

### 4.2 对话

- 输入框打字 → **Enter** 发送（Shift+Enter 换行）
- AI 逐字流式回复，带 Markdown 实时排版
- 输出过程中发送按钮变红色 ⏹，点击停止
- 顶部 **模型** 按钮切换 DeepSeek / 通义千问

### 4.3 角色

- 顶部下拉框选角色，AI 回复风格随之变化
- **＋ 角色**：自定义名称/图标/提示词（同名拒绝重复）
- 选择角色后 ✏️ 编辑 / 🗑️ 删除
- 对话自动绑定角色，切换历史对话恢复对应角色

### 4.4 语音

- 点击输入框旁 **🎤** 说话 → 自动识别发送
- AI 回复完成后自动朗读（可关闭）
- 底部下拉框切换音色（火山8种 + 腾讯3种）
- 🔊 手动朗读 / ⏹ 停止
- 麦克风测试：`/static/mic-test.html`

### 4.5 附件

- 输入框旁 **📎** → 选文件（PDF/Word/TXT/代码）
- 按钮变绿 📄 → 输入基于附件的问题
- 再次点击移除附件

### 4.6 模型参数

- **⚙️ 参数** → Temperature/MaxTokens/Top-P 滑块
- 数值实时生效，localStorage 持久化

### 4.7 对话管理

- **左侧边栏**：查看所有历史对话，点击切换
- **✏️** 按钮：重命名对话标题
- **✕** 按钮：删除（含数据库消息）
- **📥 导出** 按钮：下载当前对话为 Markdown 文件

### 4.8 知识库问答

聊天页顶部模式栏可在 **普通对话** 与 **知识库问答** 之间切换。两个模式的历史列表完全独立，切换时会开启对应模式下的新会话；**角色下拉、编辑/删除角色、添加角色只在普通对话模式显示**。

- 点击 **管理知识库** → 输入名称创建，每个用户可创建多个
- 在右侧详情中 **上传文档**（TXT/MD/PDF/Word/Excel(xlsx)/代码等），支持**一次选择多个文件批量上传**：上传过程中面板实时显示每个文件的「解析中 → 切分中 → 已切分 N 段」与整体进度条，全部入库后统一向量化并显示「向量化 x/y 段」；单个文件解析失败不影响其余文件
- **扫描版 PDF** 没有文字层时会自动转成图片做本地中文 OCR，识别结果同样入库；首次识别会加载模型，稍慢于普通 PDF
- 在分享区输入对方用户名即可分享；对方只读，可以基于该知识库提问，不能改文档或分享设置
- 所有者可移除文档、取消分享、删除知识库；删除会同步清理向量集合
- **列表折叠**：知识库详情只显示「文档」和「待审核文档」两块（不再单列表格区）；当某块超过 5 个文件时，只显示最近入库的 5 个，其余折叠，点「展开其余 N 个」查看、点「收起」还原
- 知识库问答会严格依据检索到的资料作答；资料中没有的信息会明确说明
- 模式和知识库选择保存在浏览器本地，刷新后保持

**表格识别与下载**

- 上传含表格的 Word/PDF/Excel 时，系统会结构化抽取其中的表格并记录名称、行列数与完整度（非空单元格占比，供核对解析质量）；PDF 表格用 PyMuPDF 识别线框，扫描件表格依赖 OCR 文本。表格不在知识库详情里单独成区展示，改为**在知识库问答里按问题智能推荐**：问到相关表格时直接给出原始文件下载卡片（见下文"表格智能推荐"）
- **表格按文档顺序归位**：解析 PDF 时会给每页打上页码标记，切块时文本块记录自己的页码；表格从来源（如「PDF 第3页」）解析页码后，被插入到**该页最后一个文本块之后**，不再全部堆到文档末尾。审核列表里能看到表格出现在它原本所在的章节位置（如第3页的表格出现在「3 废物分类」之后、「4 危险废物…」之前）；同页多张表按抽取顺序排列，无页码的表格（Word/Excel）仍保留在末尾不丢失
- **PDF 只收录真正的业务数据表**：受控文件每页的页眉/页脚（文件编号、生效日期、第X页 共Y页）、公司名+文档标题的页眉横幅、编制/审核/批准/会签/文件发放等审批记录栏（含与审批栏连在一起的修订记录），以及被线框误框住的零散正文，都会被自动过滤，**不算表格**；这些内容仍作为普通文字进入正文供向量检索，只是不出现在表格清单与推荐下载里。判定依据：记录字段命中数 + 行数 + 完整度 + 与文档标题/公司名相似度 + 跨页重复兜底
- **跨页表格自动合并**：一张表跨多页时（如第27页序号1-11、第28页序号12-29），会自动剔除框进来的页眉行与全空列、合并成一张完整表，命名标注页码区间（如"第27-28页-表格2"）；PyMuPDF 把空单元格返回成字符串 "None"，解析时已统一当作空处理
- **标点与合并单元格保真**：
  - PDF 表格不用 `extract()`（它会把标点剥离堆到单元格末尾、丢失合并格），而是用单元格 bbox 从页面文本层取文字（标点与原文件一致），并按 bbox 尺寸还原跨行/跨列合并格；
  - Word 表格不用 `row.cells`（它会把合并格在每个网格位置重复返回，导致预览出现多列相同文字），而是读底层 XML 的 `gridSpan`（跨列）和 `vMerge`（跨行）重建真实网格；
  - 预览里合并格按原样纵向/横向合并显示（rowspan/colspan），完整度统计不计入被合并覆盖的位置
- **表格标注来源文档**：清单与预览标题都显示「文档名 · 表格定位」，不再只显示"第27页-表格2"让人不知道出自哪个文件
- **表格预览**：抽取的表格内容在独立审核页（`/review`）里以只读块展示，可核对真实单元格（含合并单元格的 rowspan/colspan），不生成任何内容
- **下载卡片自愈**：下载链接会携带文档名；文档重新上传导致旧表格 id 失效时，后端按文档名回退到最新原件，历史聊天里的下载卡片仍可正常下载
- **下载文件名**：下载链接显式指定原始文件名，避免浏览器把带查询串的 URL 误当成文件名而存成 `download.bt` 等怪文件；若 Edge 弹出"重复下载"提示，说明同名文件此前已下过，选择"继续下载/覆盖"即可
- **下载卡片标题=原文件名**：卡片标题显示上传的原始文件名（如「WI-AH-094-2025 A5 A4 危险废物管理制度」），表格名（如「第3页-表格1」）退到副标题的"内含表格"说明——因为点击下载的是**完整原始文件**，不是单张表格，标题与下载物保持一致
- **IDM / 迅雷等下载器兼容**：下载接口对"持有链接即可下载"放行（URL 含 kb_id + table_id 两个 UUID，不可枚举）。这类下载器接管下载时会用自身 HTTP 客户端重新请求、不带浏览器 Cookie，若强制登录会返回 401 并报"无法下载 - 没有文件"；现在无 Cookie 也能正常下载原件。有登录态时仍照常做知识库权限校验
- **旧版下载链接不再报"无法下载"**：早期版本遗留的 `/api/kb/download/<id>?file=<uuid>` 链接（指向已删除/重建的文档）现在返回一个"链接已过期、请重新提问"的中文提示页；若该 UUID 恰好命中现存原件则直接下载真实文件，绝不随便挑一个文件顶替
- 上传时**原文件会留存到服务器** `kb_originals/`，删除文档/知识库时同步清理
- **人工审核把关**：上传的文档不再直接入库。解析切块后先进入知识库详情的「待审核文档」区，点「前往审核」打开**独立全屏审核页**（`/review`）：左侧列出待审核文档与全部切片，点哪块就在中间大编辑区审核（可编辑文字、**修改章节标题**、删除错误块、勾选相邻文本块合并），表格块独立只读展示但可改表格标题；右侧集中放置保存/删除/合并/驳回/通过入库操作。只有点「通过入库」才写入正式库并向量化，此前对问答检索完全不可见；「驳回」则丢弃解析结果与原件。审核页完整支持明暗双主题，文字用正文色变量，两种主题下都清晰可读。审核前不消耗向量化额度，从源头保证数据正确
  - **章节标题写进正文 + 可人工修正**：章节标题（如「1 目的」「2 职责与权限」）现在会作为**文本块的第一行**出现在正文里，审核时直接可见、可编辑，而不只是放在「章节标题」字段中。列表里每个切片下方的绿色文字就是 `section_path`（章节标题），由系统按文档结构自动识别。审核时可在编辑区顶部的「章节标题」输入框直接修改——列表显示和检索时的**整节父块聚合**都会用你改后的标题，自动识别错了也能当场纠正。表格块同理可改表格名。没设标题的块会显示「未设章节标题（点击设置）」提示
- **语义化切块**：不再按字符数硬切。段落是最小单元，短段落合并；长段落按句号/问号/叹号等句子边界断开，句子保持完整；相邻块重叠取整句；PDF 跨页段落自动重连（页间不再被强行断开），Word 段落按空行正确区分
- **结构化切分 + 父子块检索**（制度/规章类文档）：
  - 上传时自动识别「第X章／第X条／2职责与权限／2.1／一、／（一）」等标题层级，为每个切片记录 `section_path`（如 `4 危险废物的收集、包装和入库 > 4.1 危险废物的收集和包装`），审核页切片列表与编辑区都会显示该路径，便于人工核对；
  - **区分「编号标题」和「编号条款」**：`2职责与权限`、`4.1危险废物的收集和包装` 这类短且无句号的编号行才是标题；`2.1.1负责组织编制…。`、`4.1.2要求装桶材质…。` 这类自带正文的编号条款不再被误判为标题，避免每个编号行都被切成 10~30 字的碎块；
  - **相邻条款按父章节聚合**：同一章节下的多个条款会合并成块，直到接近目标大小（500 字）；不足 120 字的尾块并入上一块。以《危险废物管理制度》为例，切块数从 **65 块降到 8 块**，每块 130~870 字，语义完整；
  - **PDF 软换行自动接回**：PDF 文本层按页面宽度折行，一段话常被拆成多行（化学名、长句甚至被从中间劈开，如 `1H-茚-1-氨`）。切分时会把这类"软换行"接回同一段（中文之间不加空格），标题、编号条款、句号结尾处仍保留段落边界；审核编辑区里一段话不再显示成零散多行；
  - **折行条款开头不再丢失**：编号条款被 PDF 折行时，第一行常断在半个词上（如 `…按照要求的位置、层` + `数、高度存放…`）。以往这行因结尾无句号被误判成标题、开头整段丢失；现已收紧标题判据（编号后内容超过 20 字一律是条款），并支持标题自身被折行的情况（如 `4.3 危险废物的对外转` + `运`）。短章节并入上一块时其独立标题也会保留在正文，不再凭空消失
  - 跨页重复的页眉/页脚（公司名、文件编号、第X页共Y页）只保留第一次，粘在正文行尾的页眉片段也会切掉，但正文小标题不会误删；化学式/物料型号（如 `6-氨基-2，2，7-三氟…`）不会被误识别为章节标题；
  - 同一章节过长时仍按句子边界切成多个**子块**（精准命中），但都带相同 `section_path`；没有独立正文的纯章标题不单独成块，末尾条款自带正文时不会被吞掉；
  - 检索时先命中子块，再按 `section_path` 聚合同一章节的全部子块作为**父块**整体返回给大模型，避免"答案被拦腰截断、跨页段落回答不完整"；同节多个命中会去重，不会跨节混入无关内容；
  - 无标题文档自动回退到语义化切分，`section_path` 留空，检索回退到单块；向量检索与 BM25 关键词检索两条路径都走同一套父子块逻辑
- 在知识库问答模式下直接说「我需要××表格，给我下载」，系统会到**真实的表格库**里按名称匹配：命中则给出下载卡片，点击下载的是**上传的原始文件本身**；未命中则明确回复"知识库中没有这张表"
- **系统不会生成知识库里不存在的表格**——下载接口只能从留存原件读取，取不到就报 404，整个过程不让大模型生成表格文件

> 知识库向量检索依赖本机 Milvus。Milvus 或 Embedding 不可用时，系统自动降级到关键词检索，功能仍可使用。

## 5. API 接口

**统一响应**：`{"code": 200, "message": "success", "data": {...}}`

| 蓝图 | 方法 | 路径 | 说明 |
|------|------|------|------|
| **auth** | POST | `/api/v1/auth/register` | 注册 |
| | POST | `/api/v1/auth/login` | 登录 |
| | GET | `/api/v1/auth/me` | 当前用户 |
| | POST | `/api/v1/auth/logout` | 退出 |
| **chat** | POST | `/api/v1/chat` | 对话 |

## 9. 常见问题

| 问题 | 解决 |
|------|------|
| MySQL连接拒绝 | 检查MySQL是否运行，`.env`密码是否正确 |
| AI不回复 | 检查API Key；`curl /api/v1/health` |
| 流式无打字效果 | Nginx需 `proxy_buffering off` |
| 语音识别不工作 | `/static/mic-test.html` 诊断；检查浏览器麦克风权限 |
| Markdown渲染异常 | **Ctrl+F5** 强制刷新 |
| 代码修改不生效 | 重启服务 `python run.py` |
| 知识库检索不准 | 确认 Milvus 已启动、`.env` 已配置 `QWEN_API_KEY`；未配置时仅做关键词检索 |
| 提示"向量库不可用，已改用关键词检索" | 通常是**服务比 Milvus(WSL) 先启动**导致首次连接失败。现已支持自动重试：Milvus 就绪后 5 秒内自行恢复，无需重启；若持续提示，检查 WSL 是否已启动（`wsl -l -v`） |
| 扫描版 PDF 上传失败 | 确认已安装 `pymupdf`、`rapidocr_onnxruntime`、`opencv-python`；依赖缺失时接口会返回具体提示 |
| 知识库问答报无权限 | 分享已被取消，或对方不是该知识库所有者/被分享者 |
| Excel 上传报不支持 | 需安装 `openpyxl`（`pip install openpyxl`），并确认文件名后缀为 `.xlsx` |
| 表格显示"无原件" | 该文档是旧版本上传的，当时未留存原文件；重新上传一次即可下载 |
| 表格下载报 404 | 原文件已被清理或路径失效；请检查 `kb_originals/` 目录，或重新上传文档 |
| PDF 表格识别不全 | 扫描件表格依赖 OCR 文本，复杂/无线框表格可能识别不完整，请以"完整度"提示为准人工核对 |
| Emoji报错 | 数据库表需 utf8mb4 编码 |
